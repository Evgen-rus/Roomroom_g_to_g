# Инструкция для ИИ: копирование dropdown-плашек в Google Sheets

Нужно добавить в Python-скрипт механику, которая после записи новых строк в Google Sheets копирует dropdown-плашку из предыдущей строки в новые строки.

## Что нужно сделать

После того как скрипт записал новые данные в таблицу:

1. Определить диапазон новых строк, например `start_row:end_row`.
2. Взять ячейку-шаблон из предыдущей строки в нужной колонке dropdown, например `F{start_row - 1}`.
3. Скопировать из неё только правило dropdown/data validation в новые строки, например `F{start_row}:F{end_row}`.
4. Не копировать значение ячейки, чтобы новые dropdown-ячейки остались пустыми.

В Google Sheets API для этого удобно использовать `spreadsheets().batchUpdate(...)` с запросом `copyPaste` и параметром:

```python
"pasteType": "PASTE_DATA_VALIDATION"
```

## Важная логика

- Данные строки должны записываться отдельно, например через `values().update(...)`.
- Dropdown нужно копировать отдельным запросом после успешной записи данных.
- Источником dropdown является предыдущая строка.
- Если `start_row == 1`, копировать неоткуда, нужно залогировать предупреждение и не падать.
- Если копирование dropdown не удалось, лучше залогировать ошибку и аккуратно решить, можно ли продолжать остальную логику проекта.

## Пример идеи

```text
Новые данные записаны в строки 25-30.
Dropdown находится в колонке F.
Берём правило из F24.
Копируем data validation в F25:F30.
Значения в F25:F30 не заполняем.
```

## Уточняющие вопросы перед изменениями

Перед правками обязательно уточни:

1. В какой колонке находится dropdown?
2. Нужно ли dropdown оставлять пустым или ставить значение по умолчанию?
3. Из какой строки брать шаблон: из предыдущей строки или из фиксированной строки?
4. Что делать, если копирование dropdown не удалось: останавливать скрипт или только логировать ошибку?
5. Есть ли в проекте уже готовая функция для Google API retry/logging?
6. Каким способом скрипт сейчас добавляет строки: `values().update(...)`, `values().append(...)` или другим?

## Риск

Риск низкий, если:

- предыдущая строка всегда содержит правильный dropdown;
- копируется только `PASTE_DATA_VALIDATION`;
- значения в dropdown-колонке не перезаписываются.

Риск средний, если:

- строка-шаблон может быть пустой;
- колонка dropdown может меняться;
- после записи данных есть важная логика отметки статусов, которую нельзя ломать.
